# FP 会计方法论（M1 收尾沉淀，2026-10-04）

> 从 FP-LEDGER-m1s1/s2/s3 三片实践里沉淀的方法。适用于 ADV 所有检测类交付
> （规则、污点、secrets、二进制面），新规则/新检测器进主干前必须按此出账。

## 1. 出账时机与口径

- **新规则不单独验收**：规则 + ruleid 夹具（注解逐行一致）+ 真实仓运行三件一起出。
- **逐条判定的边界要诚实**：全量逐条是理想；工程量出界时，明示"本片不判 X 条 +
  分布留档 + 分批计划"，**禁止抽样升总体**（用户 2026-09-29 口径）。
- 每条判定必须带：位置（file:line）、上下文（代码片段）、判定（TP/FP/TP-by-design）、理由。
- 判定词汇表固定：**TP**（规则定义就该报）/ **FP**（规则语义错了）/ **TP-by-design**
  （语义对、但该处有豁免理由 ⇒ 进抑制四要素，不带豁免理由的不得写 TP-by-design）。

## 2. 抑制与账的关系

- FP-by-design 的落地形态 = `adv:allow(规则, reason, until)` 四要素（行级/文件级），
  **到期账进 suppress 门**（过期即红）。会计账里的 TP-by-design 条目必须能指出
  对应的抑制声明（或声明"片 N 补抑制"）。
- 抑制不是财务核销：底层发现仍可由 `scan` 复现（抑制只影响默认报告面）。

## 3. 真实仓靶的选择

- 至少一个**规模靶**（≥100 源文件）+ 自身工作区（自扫，验证抑制 E2E）。
- `vendor/`、第三方、生成代码一律 `--exclude`（m1s1 教训：230 条 vendor 噪音
  直接教出了这个功能）；排除决策写进账本。
- 靶太薄（<10 文件）只算冒烟不算验收（physarena 2 个 .rs 的先例）。

## 4. 判据抓到的 bug 也是交付物

每片账本必须有"被判据抓出来的问题"一节（m1s1：obj.eval 误报 ⇒ 三段语义；
m1s2：receiver 污点/导入名/tainted 建账三 bug；m1s3：suppress 门自指误报 ⇒
文档注释不是注解通道）。没有这一节的账本 = 门禁没真跑过，不可信。

## 5. 禁止事项

- 禁止用"准确率 X%"这类聚合数字替代逐条账（样本口径不明 = 不可复算）。
- 禁止把 FP 会计当成一次性验收：规则语义改动 ⇒ 受影响的旧账条目重判，
  旧账文件不删不改判定（追加勘误节）。
- 禁止在账本里写没有上下文的判定（只有 file:line 没有代码片段 = 复算不了）。

## 6. 账本命名与位置

`eval/FP-LEDGER-<里程碑><片>.md`；方法变更改本文件并提交披露。
