# GAME-BUG-TAXONOMY.md —— 游戏 bug 十五街区的扫描判定档（S190，用户 2026-09-29 清单落地）

> 来历：用户给的 15 个"代码城街区"游戏 bug 分类（物理/动画/网络/输入/AI/逻辑/资源/时间/
> UI/存档/音频/平台/并发/数值/热更安全），两条指令：**①他自己的项目（含 BSHSQ 物理引擎）
> 不许有这些 bug；②本仓扫描器要针对这些来扫**。
> 本档职责：逐街区判定"**检测归属**"——✅已有（现有工具已覆盖）/ ✅吸收（排片写静态规则）/
> 🟡有界（启发式，误报要量化）/ 🏃运行时（静态测不了，记档归项目自身判据）——并给队列。
> 判定口径沿用 [FRONTIER-CI.md](FRONTIER-CI.md)；红线照抄：零依赖 / 能力只实现一次 /
> **判据先于功能**（每条新规则配**金丝雀**：注入必红样本，先验红再上线）/ 误报要量化
> （启发式规则必须带 precision 抽样账）。

## 一、逐街区判定

| # | 街区 | 判定 | 归属与说明 |
|---|---|---|---|
| 1 | 物理碰撞 | 🟡 混合 | **双权威改位置** → ✅吸收（`arch_gate` 规则族：控制器层不许写刚体位姿，项目声明）；**池复用未重置 / 触发器重复** → 🟡 启发式（引擎特定 pattern，后片）；**CCD/穿透/抖动/粘墙** → 🏃 运行时探针（物理引擎自身的门——BSHSQ 测量协议已示范）；**帧率依赖 dt** → 🟡 启发式 + 🏃（真判定在固定步长判据） |
| 2 | 动画 | 🏃 记档 | 滑步/IK/蒙皮/混合权重都要运行时与资产数据；状态机抖动需引擎图数据——静态不假装能测 |
| 3 | 网络/多人 | 🟡 混合 | **服务器信任客户端**（与 15 同源）→ 🟡 污点（概念=不可信输入流进权威决策；`rust_taint_scan` 已有引擎，扩语言另立片）；**权威唯一 / 会话接管** → ✅ arch 规则族；**橡皮筋/插值/时钟** → 🏃 |
| 4 | 输入 | 🏃 记档 | 丢键/死区/缓冲是运行时行为；UI 事件穿透是引擎层配置——记档 |
| 5 | AI/寻路 | 🏃 记档 | 导航网格过期/群体死锁/感知都是运行时；行为树状态残留需引擎图数据 |
| 6 | 逻辑/状态机 | 🟡 混合 | **单例/全局污染** → ✅吸收（`bug_scan` 规则：Python `global` 可变 / Rust `static mut` / C# 可变 static——排片）；**生命周期未退订**（事件 += 无 -= / connect 无 disconnect）→ 🟡（需 C#/GDScript 词法面，语言面扩展另立片）；对象池 reset 同 1 |
| 7 | 资源/内存 | 🟡 混合 | **悬空/释放** → ✅已有（Rust 编译器；C# 建议接 analyzer，记档）；**每帧分配（GC 卡顿）** → 🟡 启发式（系统/Update 内新建集合——Bevy 面先做，误报要量化）；异步加载竞态 → 🏃 |
| 8 | 时间/帧 | 🟡/🏃 | 固定 vs 可变步长同 1；**回放不同步** → 🏃 记档（BSHSQ 已有逐位复现判据——项目侧已有先例） |
| 9 | UI | 🟡/🏃 | **本地化硬编码** → 🟡 启发式（UI 层用户可见字面量；误报高，先评估再排）；分辨率/安全区/焦点 → 🏃 |
| 10 | 存档/序列化 | ✅ **吸收（S191 已落地 Rust 语言面）** | **非原子写** → ✅ 静态规则 `save_nonatomic_write`（直写存档路径且目标不是临时/中间文件——与本仓 `hub_ledger` 末行截断教训同源，S187 续先例）；**版本兼容缺失** → ✅ 启发式 `save_load_no_version`（解析存档语料但所在函数无 version/schema/migrat）；损坏/原子写的"可观测后果是写到一半"本仓已实测过；云冲突 → 设计级记档。**未覆盖**：`OpenOptions` 组合式打开、C#/GDScript/Python 语言面 |
| 11 | 音频 | 🏃 记档 | 采样/循环点/3D 衰减全运行时 |
| 12 | 平台/硬件 | 🟡/🏃 | **生命周期事件缺失**（切后台/来电 handler）→ 🟡 引擎模板检查（后片评估）；死区/映射/驱动差异 → 🏃 |
| 13 | 并发 | ✅已有/🟡 | **数据竞争** → ✅已有（Rust Send/Sync 编译期拒绝——本仓零依赖红线下的天然强门）；**一帧延迟**（渲染读上帧物理）→ ✅ arch 规则族；任务顺序/死锁 → 🏃 |
| 14 | 数值 | ✅已有/🟡 | **浮点 ==** → ✅已有（`bug_scan`）；**整数溢出** → 🟡（Rust release 包装语义 + `as` 收窄启发式）；**四元数未归一化** → 🟡 启发式；单位混用 → 记档（newtype 纪律属项目侧类型设计） |
| 15 | 热更/Mod/安全 | 🟡 | 客户端权威/信任客户端 → 同 3 污点；Mod ABI/沙箱 → 记档（属引擎选型） |

**汇总**：✅已有 3 条（浮点比较、Rust 所有权/Send-Sync、死按钮族）· ✅吸收 5 条（arch 规则族×3
用途、全局可变态、非原子写、版本兼容缺失、每帧分配）· 🟡 有界 7 条 · 🏃 运行时记档 9 条。
**两句总纲**（对应用户的总结）：①静态扫描管"**结构错了必出事**"的街区（权威、生命周期、
存档、全局态、数值比较），运行时判据管"**跑起来才看得见**"的街区（时序、手感、抖动）——
**两类都要，但别假装静态能测后者**；②"换人继承动量"同源类（旧权威没停/缓存没清/状态没
原子迁移）落在**项目侧 arch 规则 + 池/状态机规则**，本仓出模板，项目各自声明。

## 三、红线复述（做这几片时必须守的）

1. **判据先于规则**：每条新扫描规则必须带**金丝雀**（夹具里注入必红样本——先证明门能红，
   再上真树）；启发式规则另带**误报抽样账**（在真实项目上抽 N 文件报 precision）。
2. **能力只实现一次**：新规则先进既有载体（`bug_scan` / `ui_check` / `arch_gate`），
   不另起第二套扫描器。
3. **零依赖**：规则引擎用既有 Rust 面（`rx-scan`）/ stdlib AST；引第三方 linter 先过选型三问。
4. **不越权**：扫描器只报告与定位；"项目不许有这些 bug"的**治理动作**（修代码/改架构）
   留给项目侧（G1 同精神）。
