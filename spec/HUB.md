# HUB.md —— 平台层设计（ADV 升级第二协议通道 + 团队自托管运行台 + 防骗验证体系）

> **范围（2026-09-28 第二轮用户指令）**：本设计属于 **ADV 仓本身**（上传/发布只对
> bfxh/ADV）——平台编排对象 = ADV 自己（自举 dogfood），**不关其他项目的事**（早期草案
> "包裹其他仓门链"的 M0 作废）。名字沿用 **ADV**，只是升级；无新品牌。
> **第三轮补充（同日）**：①平台跑与直跑**可以且必须关联**，但要有大检查——要有一个东西
> **防止平台和直跑骗过智能体**，需要大量验证体系去维持它（§六，对拍纪律源自物理引擎仓
> 的测量协议）；②本轮**只交文档**，M0 代码挂下一轮。
> **本质（用户原话「你要看清楚本质」）**：这个平台**仍然是 MCP**——MCP 工具面就是平台
> API，智能体必须能调用相关技术；网页是给团队看的第二张脸。

## 一、本质与架构判据：一份能力，两张脸

```
                    ┌─ 智能体（ZCode/Yan Agent…）── stdio ──▶ server.py（MCP 协议层）
                    │                                            │
能力层（唯一实现）───┤                                            ├─ registry.call（单一裁决点）
   tools/*.py       │                                            │   （授权门/沙盒/熔断/审计）
   hub 域新成员 ────┤                                            │
                    │                                            │
                    └─ 团队/人（浏览器）── HTTP ──▶ server_web.py（第二协议层）
                                                     │ 同样走 registry.call
```

- **任何平台能力只实现一次**（tools/ 域模块），两通道共享授权门/沙盒/熔断/审计账本。
- **智能体调用面** = 新 hub 域四工具（`hub_status`/`hub_pipelines`/`hub_runs`/`hub_run`）。
- **网页调用面** = `server_web.py`（HTTP + 静态控制台），读写都经同一能力层。

## 二、技术选型（用户：node/JS 只是前端；后端判据是"仍然是 MCP"）

| 方案 | 判定 | 理由 |
|---|---|---|
| **Python stdlib（选定）** | ✅ | 与 registry 同源：hub 工具与网页路由调**同一份**能力层；零 pip 依赖（http.server/threading/hashlib/secrets/ctypes）；授权门/沙盒/审计直接复用，无双实现 |
| Node/Express 后端 | ❌ | 能力层分叉：要么子进程转调 Python（多一跳 + 双运行时），要么重写一份（漂移） |
| Rust 后端 | ❌（现阶段） | 用户口径"不主动重写"；引擎面已原生化，编排面留 Python（判型在案） |
| FastAPI/Flask 等 | ❌ | 引第三方依赖，违零依赖红线；stdlib 足够 |

**前端（下一轮）**：vanilla JS + HTML + CSS，无框架无构建链（"node/JS 都可以，只是前端"）。
页面风格：**整体参考 GitHub 仓库页**（打开项目的那类页面：文件式清单 + Actions 式运行
列表 + 详情页），整体布局按用户自有意象，不逐像素照抄。

## 三、团队多用户（用户：不只是单个用户，是一个团队）

- **身份三源**：① 网页用户（令牌 pbkdf2 存储；首跑自举 admin、令牌只打 stderr 一次；
  **S179 起用户管理在 admin 面**——创建/改角色/删除，令牌**只此一次返回**，
  **最后 admin 不可删/降**（防锁死））；② 智能体（registry 归因 / Bearer）；③ 本机调度器。
  账本统一记 `actor`；管理动作也入账（`kind=admin`，同受哈希链保护）。
- **鉴权分层（S179 起）**：开放 = 控制台外壳 + `/api/status` **摘要态**（未登录也看得见
  平台是否降级）+ 登录端点；**读面要会话**（Cookie `hub_sid`，HttpOnly + SameSite=Strict）；
  `/api/users*` 要 admin；触发 = 会话（operator/admin）**或** Bearer（脚本/智能体兼容）。
- **并发**：ThreadingHTTPServer；账本跨进程单写者（锁文件，msvcrt/fcntl）；**资源级准入**
  （S178：`exclusive` 与任何活跃运行互斥、`shared` 并行 ≤ `UNIFIED_RX_HUB_MAX_SHARED`（默认 2）；
  活跃集 = 目录内"一运行一文件"，检查与创建在同一临界区防 TOCTOU）；**阻塞式排队未做**
  （先量后改——拒绝式 busy + 活跃可见已够本机分钟级作业）。
- **稳定/开发双实例**：稳定（`UNIFIED_RX_HUB_INSTANCE=stable`，提案端口 7741）供团队与
  智能体；开发（dev，7742）供开发；控制台横幅常驻实例身份。智能体只配稳定版 MCP。

## 四、模块划分（上帝对象防线：行数预算先行，god/dupe 门首日就在）

| 文件 | 职责 | 行数预算 |
|---|---|---|

| `hub_core.py` | manifest 严格校验（含命令首段白名单）+ 运行账本（sha256 链）+ **资源级准入** | ≤260 |

| `hub_propose.py` | 修复提案流（**隔离工作树**跑白名单机械修复 → 只出 patch；G1：永不碰主树/永不合并） | ≤140 |
| `hub_impact.py` | 静态语义选测（变更 → import 反向闭包 → 测试集；保守不漏 + 诚实退化） | ≤200 |

| `pipelines/*.json` | **纯数据**（一管线一文件，schema 见 §五） | —— |
| `scripts/hub_gate.py` | 防骗体系常驻门（§六判据机器化） | ≤200 |

## 五、pipeline manifest（与 spec/PLAYBOOKS.md 族骨架同源）

```json
{"id": "adv.gate-all", "title": "ADV 全门", "when": "合入前/手动",
 "resource_class": "exclusive", "on": ["manual"],
 "steps": [{"step": "gate", "cmd": ["python", "-X", "utf8", "scripts/local_gate.py"],
            "timeout_s": 3600, "optional": false}]}
```

- 步骤语义刻意最小：**顺序 + 固定 argv + 超时**；无循环、无内容分支、无嵌套
  （Node-RED/n8n "面条流"的社区实测教训落在数据格式上就是这条红线）。
- 校验：未知字段即拒（默认严苛）；id 唯一且与文件名一致；步骤 1..16；argv 1..32 段。

## 六、防骗验证体系（本档核心：平台跑 ↔ 直跑的一致性如何被**持续**保证）

> 用户定调：平台跑和直跑可以关联在一起，但要有**很大的检查**；要有一个东西防止平台和
> 直跑**骗过智能体**；需要大量验证体系去维持它。对拍方法论（交错 A/B / 机器独占 /
> 窗口均值 / 金丝雀 / SKIP 显式化）源自物理引擎仓（BSHSQ）测量协议，平台层照搬。

### 6.1 威胁模型（谁在什么位置骗谁）

| # | 威胁 | 具体形态 |
|---|---|---|
| T1 | 平台虚报绿 | 门没真跑 / 跑错目录 / 跑了弱化版却报 OK |
| T2 | 平台漏报红 | 失败被吞成 skipped；SKIP 被算进"绿" |
| T3 | 账本被改 | 事后改记录 / 重放旧的成功记录 |
| T4 | 环境漂移 | 平台跑的环境与直跑不同 ⇒ 平台绿 ≠ 直跑绿 |
| T5 | runner 说谎 | 退出码误报 / 日志被截断伪造 |
| T6 | manifest 被换 | 管线声称跑 A 实际跑 B（rug-pull） |
| T7 | 仪器失效 | 门本身瞎了（规则过期/引擎坏），连续给绿 |

### 6.2 九道机制（每道：机制 → 挡哪个威胁 → 复用资产）

1. **双跑对拍门（常驻，非一次性验收）**——同 commit、同语料，平台跑与直跑**交错 A/B**
   （机器独占锁内），判据 = 退出码 + 判定行 + 步骤摘要**逐字节一致**；timing 敏感量取
   窗口均值（单点差可能只是相位）。→ 挡 T1/T4。复用：perf_lock 独占、测量协议交错 A/B。
2. **金丝雀必红/必绿注入**——对拍语料常驻两类夹具：植入已知缺陷（**必红**）与干净样本
   （**必绿**），平台必须各就各位。**"说绿之前，先证明抓红的能力是新鲜的"**：平台连续
   对拍抓不到注入红 ⇒ 判仪器失效（T7），状态页红。→ 挡 T1/T7。复用：快照棘轮门的
   金丝雀纪律（"门真在扫吗"要用金丝雀证明）。
3. **运行指纹（argv/cwd/env/HEAD/manifest 绑定）**——每个 run 记录：manifest sha256、
   git HEAD、dirty 位、实际 argv、cwd、env 关键键哈希（UNIFIED_RX_* / PYTHONUTF8）、
   工具链版本（python/cargo）。智能体可核对"平台跑的就是我以为的那个门"。
   → 挡 T1/T4/T6。manifest 指纹改动即新指纹（rug-pull 防护，mcp-scan 启发）。
4. **原始产物哈希入账**——日志文件的 sha256 + 字节数写进账本行；**退出码取自 OS**
   （Popen.wait 返回值），不经任何中间解释层。智能体可用自己的工具独立重算日志哈希
   交叉验证。→ 挡 T5。
5. **SKIP 显式化，绿的定义收紧**——"平台绿" ≡ 所有必跑步骤 exit==0 **且**无未标注 SKIP；
   SKIP 单列一栏，**SKIP 不算绿**（本仓既有纪律：计时档默认 SKIP 不静默、不算双绿）。
   → 挡 T2。
6. **账本哈希链 + 判定封印**——append-only + prev-hash（篡改即链断）；每条 final 行带
   **封印** = 判定相关字段（管线 id / manifest 指纹 / HEAD / 退出码 / 步骤摘要 / 日志
   哈希）的再哈希——**同输入同封印**，跨机可复核。→ 挡 T3。复用：mimosa 封印、
   vuln_hunt seal 口径。
7. **runner 自身被攻击**——平台面进自攻巡航（auth_gate_sweep / input_fuzz / big_input
   周期打 hub 工具与 HTTP 面）；注入"假 runner / 假退出码"的对抗测试常驻（先记基线再
   验红的金丝雀形态）。→ 挡 T5/T1。
8. **智能体侧复核义务（协议化，信任最小化）**——`hub_runs` 每条结果带 `how_to_verify`：
   独立复核命令 + 期望指纹 + 期望判定行。**防骗不依赖平台自觉**：智能体/人可以完全不
   信任平台地复核（"不信任，去验证"）。→ 这是"防止平台和直跑骗过智能体"的最终落点。
9. **漂移报警（仪器坏了先报仪器）**——对拍连续 N 次不一致 / 金丝雀失明 / 链校验失败 ⇒
   平台进入 `degraded` 状态（横幅红 + hub_status 如实返回），**不带病报绿**。→ 挡 T7。

### 6.3 判据表（落地即测，常驻机器门 `scripts/hub_gate.py`）

| 判据 | 预算 | 量法 |
|---|---|---|
| 对拍一致率 | 窗口内 100%（不一致即 degraded） | 双跑交错 A/B |
| 金丝雀检出 | 必红 100% 命中、必绿 0 误伤 | 注入语料 |
| 篡改注入 | 改账本任意一节必红 | 金丝雀（先记基线再验红） |
| 指纹完备 | 每条 final 行八项指纹齐缺一即红 | schema 校验 |
| how_to_verify | 每条结果可独立执行且结论一致 | 抽查执行 |
| 授权矩阵 | 无令牌/坏令牌/越权角色必拒；MCP 无授权必拒 | 矩阵测试 |
