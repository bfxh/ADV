# 主张完整性（S194）——把「表述幻觉」变成可机器复算的那一半

> 用户口径（2026-09-29）：「**减少这些幻觉，也是一个审核，扫描器 CI CD 要自动检查这些**——
> 不要把过程变成东西、把关系变成属性、把条件变成本质、把局部变成总体、把解释变成终点，
> 还有其他的。」

本文档回答三件事：①这五类**能不能**静态判（四轮实测）；②能判的那一半落成了什么（本片交付
`scripts/claim_gate.py` + `spec/claim-checks.json`）；③我自己还有哪些干扰/幻觉（自审清单）。

---

## 一、四轮实测：词表版不可判，**造词表门 = 造假门**

测量面：`skills/**` + `spec/*.md` + `docs/**` + `README.md` = **52 文件 / 8109 行**。

| 轮次 | 判法 | 结果 |
|---|---|---|
| v1 | 字面词表（每类一组正则） | `过程→东西` **0** · `代理当目标` **0** · `关系→属性` 3（读码：全是正常表述）· `条件→本质` 15（假阳性来自"引用用户原话"、条件写在别句）· `局部→总体` **106**（绝大多数是真审计的正常表述）· `解释→终点` 5 · `时间戳当事实` 4 |
| v2 | 改判"绑定缺失"（行级：主张缺锚） | R1 量化主张缺锚 **201** · R2 普遍断言无条件 **152** · R3 完成态缺锚 11 · R4 只归因无动作 5 · R5「全绿」缺范围 **40** —— 口径没对准仓内写法（锚常在正文/相邻行） |
| v3 | 句级 + 锚集合扩为"命令/路径/例数/步数/版本/S 编号/日期/SHA" | R1 **84** · R2 **20** · R3 50 · R5 49 —— 读码后仍以假阳性为主（capability 描述、验收定义被误命中） |
| v3′ | 再修锚（加大写 token/测试夹具名/例数形态）+ 只留**断言式**普遍化 | 完成态/全绿缺锚 **23** · 断言式普遍化 **8** —— 而 **8 处全是"该绝对化"的政策不变量**（「扫描对象永远是复制品」「永远不允许宣称项目安全」「裁决永远在智能体」） |

**结论（这一条本身就是交付）**：这五类在**散文层不可靠地可判**——四轮里假阳性始终压过信号，
而最后一轮恰好说明：**绝对化语言在工程政策文档里往往是刻意的，不是幻觉**。
⇒ 在本仓造一个"表述词表门"会变成**见谁都报的假门**，正是本仓 T7「仪器失效」要防的东西。
**不造。** 判据要能证伪，证不了伪的判据不上门链。

可复现：探针脚本留在会话临时目录（`s194_*_probe.py`），命令与数字见本表；任何一轮都能重跑。

## 二、五类的**可判等价形式**（结构层，不是词表层）

把"句子长什么样"换成"**条目之间有没有绑定**"——本仓的产物本身是**结构化**的，这才是抓手：

| 用户点名的类 | 它在本仓的真实形态 | 可判的结构等价 | 状态 |
|---|---|---|---|
| **把过程变成东西** | **当时的观察被固化成文档里的事实**，然后随代码漂移（例：README 长期写着「71 个工具」「门 18 步」） | **数字主张 ↔ 真值源**：每条登记的数字必须能从仓内复算出来；不一致 ⇒ 红（找不到也红） | ✅ **本片落地** `claim_gate` |
| 把关系变成属性 | 谈依赖/调用只点名一端（"它的依赖"），或文档里的架构主张找不到对应的规则 | **关系断言必须双端 + 引规则 id**（`arch-rules.json` 的 `from`/`import` 已是双端形态；文档侧未接） | 🔜 队列 |
| 把条件变成本质 | 无条件写"必然/总是"（**实测：修口径后 8 处全是该绝对化的政策**，见上） | **普遍断言必须带限定或档位**（门链已有 `fast/full/timing`、arch 规则已有 `scope`）| 🔜 队列（文档侧） |
| 把局部变总体 | 单点/单次测量被写成普遍结论 | **量化结论必须带样本范围**（`stat_judge` 已有分辨力字段；CI 已有 EVIDENCE 行机制）| 🔜 队列 |
| 把解释变成终点 | 只写"根因是 X"，没有修法/判据/下一步 | **ROUNDLOG 条目格式**：归因必须配动作或判据 | 🔜 队列（实测 5 处待读码定精度） |
| （我的补充）**时间戳当事实** | "已否证/已修复"没有锚（本仓既有教训：否证标签是时间戳） | **完成态主张必须带版本/S 编号/日期** | 🔜 队列（修口径后 23 处） |

**边界（明说）**：本档不做跨句/跨文档的语义推理——"这句话是不是把条件偷掉了"只有人和模型能判；
本仓能自动看住的是**声明与真值之间的绑定**，以及**格式契约**。别把这里当"幻觉检测器"。

## 三、本片交付：主张可复算门（`claim_gate`）

- **登记表**：`spec/claim-checks.json`——每条 = `{id, file, pattern, expect[], why}`；
  数据声明式（加一条主张 = 加一行数据，不是加代码）。
- **真值源四种**（仓内、零依赖、夹具可替换）：`selftest:…`（跑 `server.py --selftest` **真路径**）·
  `steps:…`（ast 解析 `local_gate.STEPS`，不 import）· `count_re:<文件>:<正则>` · `json_len:<文件>:<点号指针>` ·
  `profile:<名>`（用 `registry.profile_from_env()` 自己的域集合算件数——**域清单不复制进门里**）。
- **fail-closed**：登记表缺失 / 坏 JSON / 空登记 / 条目缺字段 ⇒ 红；**主张找不到也红**
  （"账没了"与"账错了"同罪）。
- **接线**：`local_gate` 快档一步（`claim-gate`）+ `core.yml` 显式 step + `test_s145` 步表锁步。
- **本片顺手修的真账**（门没白装，三处 README 陈旧数字）：

  | 位置 | 曾写 | 真值 |
  |---|---|---|
  | 设计哲学 | 71 个工具 | **86** |
  | 门清单 | 34 项 / 本地门 18 步 / 速档 14 步 | **32 步 / 快档 25 步** |
  | 快慢门 | 快门 6 步（4 秒级）/ 全门 9 步 | **快档 25 步（~21 秒）/ 全档 29 步** |

  ⚠️ 顺带演示了**预防性**那一面：本片接线时往 `local_gate` 加了一步（`claim-gate`），
  README 的 31/24 立刻不成立——门在**改代码的同一轮**就报了出来（先修成 32/25/29 才绿）。
  这正是"过程变东西"的另一半：**不只是旧账，任何一次改动都会让文档数字过期**。

- **判据**（`tests/test_s194_claim_gate.py`，8 例）：真仓逐条复算绿 · 登记表指向的文件都存在 ·
  **探针自洽**（`steps:` 与 `local_gate.STEPS` 逐档一致——本片踩过 `literal_eval` 吞异常把计数
  悄悄变 0，是门判红才发现的）· 金丝雀红三种（**文档数字错** / **真值漂移**（文档没跟）·
  **主张找不到**）· 未知真值源红 · fail-closed 四态。
- **变异金丝雀两轮全还原**：复算变空操作 ⇒ 4 红；档位解析失效 ⇒ 2 红（含探针自洽例）。

**为什么这不是"又一个假门"**：它的判据是**复算**（真值源是仓内可执行事实），
"绿"意味着"文档里的数字今天仍然算得出来"——这是能被证伪的（`真值漂移` 那条金丝雀就是）。

## 五、队列（下一步可做的结构判据，各自先做精度账）

1. **ROUNDLOG 格式判据**：条目须含「证据：」；只有根因没有修法/判据 ⇒ 红（先读那 5 处定精度）。
2. **完成态要锚**：「已完成/已否证/全绿」必带 S 编号 / 版本 / 日期 / 门名（修口径后 23 处待分类）。
3. **架构主张引 rule id**：文档谈"某层不许依赖某层"必须指向 `spec/arch-rules.json` 的规则条目。
4. **性能主张带口径**：文档里的性能数字必须指向 EVIDENCE 行或 `stat_judge` 的分辨力字段。
5. **日志 vs 活文档的口径**（本片已定，写进纪律）：**ROUNDLOG 是带时间戳的当时值**，不进可复算门；
   活文档（README / skills / spec 非日志）里的数字必须进——不然就是"过程变东西"的温床。
