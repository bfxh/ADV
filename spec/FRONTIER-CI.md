## 一、逐条判定（吸收 / 有界 / 不吸收）

### ① 语义 diff 引擎（AST 级变更影响 → 语义选测）✅ **吸收（本轮落地）**
- **真缺口**：现有 TIA 是**动态**（要先跑过一次才有依赖集）+ 进程内状态（跨重启不保留）；
  缺"只看 diff 就能给出受影响面"的**静态**口径。
- **落地**：`hub_impact`（平台层）= 变更集（git diff ∪ 未提交）→ **import/符号闭包**（反向可达）
   → 受影响测试与模块 + **保守退化**（拿不准→全量）+ 账本留痕。
  第一片用 stdlib AST（零依赖、可测、快）；第二片叠加 `rx-scan callgraph` 的符号级边。
- **判据**：不漏（传递闭包必然覆盖）、退化显式（fallback=full + reason）、与全量结论对拍。

### ② CI 热重载（文件监听 + 增量检查守护）🟡 **有界**
- **已有**：`ide_build --watch` + `cache` 增量。缺的是"守护进程 + 编辑器内联错误"——
  那属**宿主/编辑器侧**，不属于本仓（工具箱不做 UI）。
- **第一步动作**：把 watch 从轮询升级为可选 `notify` 依赖？**不**（零依赖红线）；
  改为把"增量**门**"做进平台：`hub_run` 已可按管线跑，watch 语义交由宿主调用触发。

### ③ 可组合模块生态（带版本/依赖/测试的跨平台 CI 模块）🟡 **有界（第一片已落地，S187）**
- **已有**：manifest（数据声明式、含 `evals` 字段）+ CD-PLATFORM 的跨平台腿 + 门链。
- **缺口**：版本/依赖解析/注册中心。**判定**：跨平台"编译到任意 CI 配置"＝已有 GitHub 腿；
  "模块带版本"＝git tag/commit 即可承载（不必造包管理器）。
- **本轮落地**（`hub_manifest.py`）：manifest 增可选 `version`（形如 1 / 1.2 / 1.2.3）与
  `requires`（条目 `id` 或 `id@版本`；非自引用、不重复）。**校验器认格式，不引解析器**——
  这是本档红线的直接体现，不是省事。
- **"没有解析器"必须看得见**：`missing_requires` 把不满足分两类如实列出——id 不在本目录
  ⇒ `（缺 adv.nobody）`；带 `@版本` ⇒ `（版本未解析）`。**假装的版本校验比不写更糟**（验证者会
  以为约束被满足过）。`hub_pipelines` 输出 `version`/`requires`/`missing_requires`。
- **判据**：防骗门 `manifest-version-requires`（第 20 项：认合法 + **8 类非法必拒** +
  两类缺口分列 + **磁盘 round-trip**——只验校验函数存在不够，字段必须真接到加载路径上）。

### ④ P2P 构建缓存网络 ❌ **不吸收**
- 理由：libp2p/quinn/sccache 兼容面全是第三方（违 `[dependencies]` 恒空与纯 stdlib 红线）；
  本仓定位是**本地优先单机工具箱**，不是分发网络；如要做应立独立项目（本档记档，不占本仓轮次）。

### ⑤ 可验证凭证（VC/DID/Ed25519）🟡 **有界（骨架 + 凭证形状已落地，S187；签名仍待定）**
- **已有**：seal + 哈希链 + 审计账本已构成"**可验证**"的核心（同输入同封印、篡改即断链）。
- **缺口**：**非对称签名**与 DID——纯 stdlib 无 Ed25519；`cryptography` 属第三方。
- **本轮落地**（`hub_vc.py`）：`hub_runs` 每条最终行附**构建凭证形状**（vc-shape/1）：
  `issuer`（actor/trigger）· `issued_at` · `subject.source`（git head / dirty / manifest 哈希）·
  `subject.environment`（python / cargo / env 键哈希 / cwd）· `subject.trace`（逐步 exit + 双流
  日志哈希）· `seal` · `ledger`（链上 hash/prev_hash）· `proof`。
- **签名档位如实标注 `unsigned`**（`proof.type=none`，理由写进凭证）：本凭证是**内容寻址 +
  链条锚定**，能验"记录未被改"，**不能**验"谁签的"——照抄 W3C VC 的 `@context`/`type` 会让人
  误以为能在 VC 生态里验证，故**刻意不套**。
- **凭证是账本最终行的纯函数**：谁拿到 `runs.jsonl` 都能独立重算
  （`python -X utf8 scripts/hub_gate.py --credential <run_id>`），不依赖平台、不依赖运行期内存。
- **判据**：防骗门 `credential-vc`（第 21 项：形状齐 + 账本行纯函数 + **子进程回放两个复核
  入口** + 篡改必变 + 轨迹与封条同口径 + 如实 `unsigned`）。
- **本片最有价值的产出是修到门自己骗自己（两条，都是"判据空过/假红"）**：
  ① `--seal` 复核入口用 S177 前的旧键 `log_sha256` 重算封条 ⇒ **所有现行运行的封条复核都
  假红**（而它正是 `how_to_verify` 广告给用户的那条命令；仓内单测用的是**正确**键，
  所以从没人发现）⇒ 修成**按记录代次取键**（新旧两代账本行都能复核），判据改为**子进程
  回放**这条真路径；
  ② 门里 `auth-matrix` 的"MCP 无授权必拒"在**空工具面**下空过——本门进程从没导入 `tools`，
  `_TOOLS` 为空，而**未知工具同样回 `ok=False`** ⇒ 断言恒真（实测 `tool_count=0`）⇒ 修成
  先把"注册面非空 + 已知工具可解析"一并纳入判据，并新增从门**自身导入上下文**出发的回归测试。

### ⑥ 混沌工程（对 CI 自身注入故障）✅ **已落地第一片（S183）**
- **已有**：busy / 超时 / 篡改 / 链断 / 陈旧护栏 / `GATE_FORCE_FAIL` 注入。
- **本轮落地**：两条**写故障**注入（账本位置被占位、日志目录被占位）——
  **复现证据（修复前，这是本片最有价值的产出）**：账本不可写时 `run_pipeline` 抛异常
  **且留下一条 exclusive 活跃位** ⇒ **平台被自己锁死**（后续运行全被拒）、且无账可查；
  日志目录不可写时异常直接冒泡（未结构化）。
- **修法**：①`admit` 之后的**一切**进 `try/finally`（任何异常都释放活跃位）；
  ②start 行写失败 ⇒ **如实拒绝执行**；③步骤 IO 故障 ⇒ 记 final `red` + 错误文本；
  ④final 写失败 ⇒ 返回 `ledger=unwritable`（**不静默报绿**）；⑤读路径容错（账本不可读
  返回空表不崩）+ **`verify_chain` 对"存在但不可读"直接判 `ok=False`**（空表的"链 OK"
  是假绿）；⑥`hub_status`/`/api/status` 增 `storage_writable` 探针 ⇒ 坏存储时 **degraded
  可见**（"平台现在能不能干活"一眼可见）。
- **判据**：防骗门 `resilience-write-fail`（17 项中的第 17 项：两条注入 + 一条对照）；
  `tests/test_s183_resilience.py` 6 例。
- 下一步（排队）：部分写坏（截断行）与磁盘满的近似注入。

### ⑦ 数字孪生环境（容器/microVM 复制生产）❌ **不吸收**
- 理由：需容器化与生产形态；本仓明确"本地直跑、无容器化"（spec/HUB.md 不做清单）。
  数字孪生的可吸收部分（"环境指纹"）**已在**：运行指纹八项（manifest/git/env/toolchain）。

### ⑧ CI 记忆系统（失败/修复/决策知识图谱 + 语义检索）✅ **已落地（S184）**
- **已有**：`lesson` 教训库（关键词召回）+ 账本 + ROUNDLOG。
- **本轮落地**：失败 ⇒ `hub_lesson` 自动草稿——**同库同格式**（复用 `tools/learn` 的读写与
  `{id,text,ts,recall_count}` 格式 ⇒ 智能体 `lesson(action="recall")` 直接搜得到）；
  草稿含**账本互链**（run_id + `--seal` 复核命令）+ **错误签名去重**（同签名不重复写）；
  `hub_runs` 对最近的 red 运行附 `recall`（"上次怎么修的"）。
- **⚠️ 修到的自污染（本片最有价值的产出）**：首版把**金丝雀的"故意失败"**也写成教训
  ⇒ 每跑一次门就往真库刷一条（实测真库被写进 `adv.canary-bad`）。修法三件：
  ① `trigger=="canary"` 或 `actor=="gate"` 不写；② **默认库随数据根隔离**
  （`UNIFIED_RX_HUB_ROOT` 被显式设置时落 `<root>/lessons.jsonl`）⇒ 测试/判据自动不碰真库；
  ③ 显式 `UNIFIED_RX_LESSONS` 优先级最高。
- **判据**：防骗门 `failure-memory`（第 18 项）；`tests/test_s184_memory.py` 5 例
  （含"同库同格式"跨面验证：用 learn 的读取器读回平台草稿）。
- 缺口（记录不追）：语义检索（嵌入=第三方，违零依赖）仍走关键词口径；图谱化同理。

### ⑨ 信用点系统（资源公平）✅ **已落地（S185）**
- **已有**：QPM/日量熔断 + 资源级准入 + 账本按 `actor` 记账。
- **本轮落地（最小兑现＝per-actor 并发配额）**：`admit` 的第三层闸门——同 actor 的 `shared`
  并行 ≤ `max_per_actor()`（默认 **1**，`UNIFIED_RX_HUB_MAX_PER_ACTOR` 可调）；超出**如实拒**
  且理由可读（含 actor 名与上限）；`exclusive` 不受此限（它受全局互斥）；**空 actor 不计入**
  （兼容既有测试/手工占位路径，不改旧语义）。`hub_status` 增 `max_per_actor` 与
  **`active_by_actor`**——"谁占了多少"一眼看到（配额可见性）。
- **判据**：防骗门 `per-actor-quota`（第 19 项：同 actor 拒 / 异 actor 放行 / env 可调生效 /
  exclusive 不受限 / 计数正确）；`tests/test_s185_quota.py` 7 例（含端到端"actor 真的进准入"）。
- 记录不追：货币化与信用点账本/CRDT 跨机同步——本仓单机、无多机面。

### ⑩ 假设检验平台（A/B + 显著性，而不是通过/失败）✅ **已落地（S182）**
- **先量的结果（独占机器 7 轮，2026-09-29）**——量就是对旧判据的否证：
  单轮比值极差 **0.15–0.54**，并**三次抽到 ≥0.95**（secrets 1.001 / search 0.998 /
  semantic 1.272，机器独占）⇒ 现行"单点比值 vs 固定阈值"**必然假红**；
  而中位数稳定（0.53–0.86）。
- **落地**：`scripts/stat_judge.py`（纯 stdlib：Bootstrap 中位数区间，**播种**保确定性）
  + `perf_gate` 口径升级为 **K 轮采样（默认 5）→ 中位数 + 95% 区间 → 三态**：
  `pass`（区间上界 ≤ 限）/ `inconclusive`（区间跨阈——**不把噪声当结论**，默认放行，
  `PERF_STRICT=1` 计红）/ `fail`（点估计与区间下界双超阈——真回归）。
- **判据**：防骗门 `stat-judge`（三态 + 确定性 + 小样本诚实，噪声带用**实采数据**）；
  `tests/test_s182_stat.py` 6 例（含"实采 semantic 不得判 fail"）。
- 下一步（排队）：把 cli-bench 的计时判据也接同一个统计模块；`inconclusive` 频发时
  收紧阈值或换指标（**有区间才能做这个决策**）。

## 三、红线复述（做这十条时必须守的）

1. **零依赖**：纯 stdlib / `[dependencies]` 恒空——凡需要 libp2p / 嵌入模型 / Ed25519 库的，
   要么降级实现，要么记 C 档（不假装做到）。
2. **能力只实现一次**：新增能力先查「本档 §零 盘点表」，**复用**（tia/impact/callgraph/lesson/
   perf_gate/seal），不得另起一套（dupe 门会拦）。
3. **判据先于功能**：每条落地必须带机器判据（防骗门 / 单测 / 全门），且判据要能**抓到自己的
   假实现**（本项目已有三次实例：假流式 `gap=0.00s`、准入竞态、git 钩子 GIT_* 变量）。
4. **不越权**：平台只出提案/证据（G1）；一切"改代码/合并/发布"留给人或智能体。
